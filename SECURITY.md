# Security Policy

## Supported code

This is pre-release research software. Security fixes are applied to the latest
state of the default branch. Historical scripts, local experiment artifacts,
and files outside the public release allowlist are not supported releases.

## Report a vulnerability privately

Use the repository's **Security** tab and select **Report a vulnerability**. Do
not open a public issue or attach sensitive material to a discussion. If private
reporting is unavailable, contact a maintainer through a private channel listed
on their GitHub profile and ask to establish a confidential reporting channel.

Please include the affected commit or version, expected impact, environment,
and the smallest synthetic reproducer you can provide. Do not include research
images, masks, checkpoints, unpublished results, credentials, institutional
usernames, or local and HPC filesystem paths.

Accidental exposure of non-public research material is treated as a security
incident. Stop accessing or redistributing the material and report the exact
repository path plus whether it was downloaded. Do not test university, HPC,
cloud, or other third-party systems without explicit authorization.

The maintainers will validate reports and coordinate fixes or advisories as
capacity permits. This research project does not promise a response-time SLA.
Please keep the report confidential until a coordinated disclosure is agreed.

## Scientific issues

Model errors, reproducibility concerns, and unsupported scientific claims are
important but are not normally security vulnerabilities. Report those through
the issue tracker unless they also expose confidential data, credentials, or a
system security weakness.
