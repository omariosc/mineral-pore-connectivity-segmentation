# Reproducibility and evidence audit

Date: 20 August 2026  
Scope: manuscript, PPTX, saved masks/splits, training and evaluation code, logs, checkpoints, generated metrics, and publication figures  
Decision: **historical performance is exploratory and cannot be submitted as confirmatory test evidence**

## Verified facts safe for the current draft

- The recovered corpus contains 100 label masks of 2048 × 2048 pixels.
- Direct mask enumeration gives 419,430,400 pixels:
  - C0: 2,435,775 pixels, 0.580734%;
  - C1: 52,415,075 pixels, 12.496728%;
  - C2: 364,579,550 pixels, 86.922538%.
- `results/step3_coco_dataset/splits.json` declares 80 training, 10 validation, and 10 test images.
- The saved masks encode C0=0, C1=1, and mineral matrix=255. Any three-class loader must map 255 to C2.
- The architecture source implements a U-Net-style encoder--decoder with dilated multiscale blocks, spatial attention gates, boundary-refinement blocks, and optional deep supervision. The recovered main config disables deep supervision.
- The supplied PowerPoint contains useful source imagery but is not safe to export as a journal figure because many objects extend beyond the slide canvases.

## Historical-result blockers

### Patch leakage

The 2025 final training log generated 900 patches from all 100 images and then reported 720 training and 180 validation patches:

- `logs/baseline_final_1601389.out`, lines 37--46.

The historical loader used `random_split` on patch indices. Patches from one source tile could therefore occur in both training and validation. The recovered 80/10/10 image manifest was not the executed split. All archived validation scores are exploratory.

The current loader has since been repaired to allocate whole image IDs before constructing train, validation, and test datasets. This is the correct basis for a rerun, but it does not validate old outputs.

### Test evaluation did not produce ground-truth metrics

- `results/final_evaluation/metrics.json` reports 20 processed images but zero images with ground truth. Its baseline, threshold, and confusion objects are empty.
- `results/final_model_evaluation/evaluation_metrics.json` is empty, while the alternative metrics file contains zeros and NaNs.
- The threshold-evaluation job crashed during model construction (`logs/baseline_final_1601389.err`, around line 181). The shell still printed “complete” because it did not stop after the failed Python command.
- The threshold evaluator was written to process only three of the ten declared test IDs.

No historical test IoU, Dice, precision, recall, AUC, mAP, confidence interval, or post-processing gain is recoverable from these files.

### The 20 available raw predictions are not a held-out test set

`scripts/generate_raw_predictions.py` selects the older ablation checkpoint and hard-codes 20 image names. Mapping those names to `splits.json` yields:

- 17 training images;
- 2 validation images;
- 1 test image.

The set must not be described as held out or used for a test figure.

### Final checkpoint identity is missing

The only local checkpoint found is:

```text
results/ablation/baseline/checkpoints/best_model.pth
sha256 bb7529e997be28f36906cbce3321ead918907560c58908676b43aa938483eb74
```

No checkpoint for final job 1601389 is present locally. Exact final-model identity cannot be reconstructed without AIRE or another archive.

### Generated metrics and figures include estimates or synthetic data

- `results/final_evaluation/updated_metrics_summary.json` labels its performance numbers `estimated_metrics`.
- `scripts/quick_metrics_summary.py` describes them as estimates based on typical performance.
- `scripts/generate_paper_figures.py` hard-codes confusion percentages and creates parametric ROC curves because raw probabilities are absent.
- `scripts/update_all_metrics.py` synthesizes ground truth when it is missing.
- `results/final_evaluation/aggregate_stats.json` counts only 12,214,840 pixels for 20 nominal 2048² images and leaves roughly 37% as “other”; it is not a valid ground-truth prevalence source.

The previous values `0.0352/0.4821/0.9234`, refined C0 `0.0693`, the “0.039% prevalence,” ROC/AUC, confusion matrices, and mAP must not be reused without a new evaluation.

### Run metadata are internally contradictory

The executed final job indicates multiscale attention U-Net, topological loss, class weights 20/5/1, learning rate 0.0005, disabled transforms, and an NVIDIA L40S. The autogenerated summaries instead describe strong augmentation, MixUp/CutMix, ResNet34 U-Net, and generic loss/scheduler values. These summaries contain hard-coded metadata.

The field named `best_pore_iou` is also not a pure IoU. The trainer computes a combined selection score from mean pore IoU and weighted F1. Existing experiment-ranking figures mislabel that quantity and are not publication evidence.

### The recovered topology loss does not optimize the claimed topology

`src/models/topological_loss.py` thresholds predicted probabilities, converts masks to NumPy, and returns connected-component statistics as non-differentiable values. The Euler term is fixed to zero. Only the smoothness term provides a gradient. The historical claim of topology-aware optimization is therefore unsupported.

## Required confirmatory package

The next authoritative run must preserve:

1. sample/mosaic/tile provenance and a grouped split manifest;
2. exact input and label checksums;
3. resolved configuration and command line;
4. source commit and environment lock;
5. random seeds and complete logs;
6. selected checkpoint plus SHA-256;
7. validation-only threshold/post-processing search;
8. per-image probabilities, raw predictions, optional refined predictions, and labels;
9. per-image and per-group metric tables;
10. group-aware confidence intervals;
11. repeated-seed controlled ablations; and
12. exact hardware/runtime protocol.

Every number in the abstract, Results, figures, tables, Discussion, Conclusions, highlights, and cover letter must be generated from those files.
